## 9 — Defects Discovered and Resolved During P4

### Defect 1 — `expiresAt` included in preview token hash

**Severity:** Critical (13 of 38 tests failing)  
**Root cause:** `buildPreviewToken()` hashed `expiresAt` as part of the state fingerprint. At confirmation, `expiresAt` was recomputed at a different millisecond, producing a hash that never matched.  
**Fix:** Removed `expiresAt` from the hash. Token now encodes state only. `expiresAt` returned as metadata alongside the token.

```diff
- payload = JSON.stringify({ actorId, entityType, targetProvenance, stateFingerprint, expiresAt })
+ payload = JSON.stringify({ actorId, entityType, targetProvenance, stateFingerprint })
```

**Stale detection still correct:** any concurrent change to `dataProvenance` or `updatedAt` produces a different `stateFingerprint` → different token → 409.

### Defect 2 — Payload fingerprint not persisted in audit row

**Severity:** High (1 test failing — `IDEMPOTENCY_KEY_REUSED` never thrown)  
**Root cause:** Repository stored `idempotencyKey: batchId:recordId`. Service parsed `:fingerprint:` suffix from this field, which was always absent → `storedFingerprint` always `null` → key reuse with different payload silently returned idempotent result.  
**Fix:** Repository now stores `idempotencyKey: batchId:recordId:fingerprint:hash`. Service extraction works correctly.

```diff
- idempotencyKey: `${idempotencyKey}:${record.id}`
+ idempotencyKey: `${idempotencyKey}:${record.id}:fingerprint:${payloadFingerprint}`
```
